## Part 2: 10 ORM queries, new set (30 min)

These are different from Day 4's, so you can't just recall answers. Use the Day 3/5 data, and add more rows if needed.

1. Published posts by `alice`, newest first.
2. Posts that are **drafts or** have no categories.
3. Posts whose title or body contains "orm" and that were created this year.
4. The 5 most recent comments, with each comment's post and author loaded in **one** query.
5. All posts with authors (one query) and categories (one extra query).
6. Posts that have **no** comments.
7. Posts with their like count, ordered by most liked.
8. Usernames of everyone who has commented on any post, no duplicates.
9. For each category, the number of published posts in it.
10. All posts, but each post's `comments` prefetch contains only comments containing "great".

<details>
<summary>Answers</summary>

```python
from django.db.models import Q, Count, Prefetch
from django.utils import timezone
from django.contrib.auth import get_user_model
from posts.models import Post, Comment, Category

User = get_user_model()
alice = User.objects.get(username="alice")

# 1
Post.objects.filter(author=alice, status=Post.Status.PUBLISHED).order_by("-created_at")

# 2
Post.objects.filter(Q(status=Post.Status.DRAFT) | Q(categories__isnull=True)).distinct()

# 3
Post.objects.filter(
    Q(title__icontains="orm") | Q(body__icontains="orm"),
    created_at__year=timezone.now().year,
)

# 4
Comment.objects.select_related("post", "author").order_by("-created_at")[:5]

# 5
Post.objects.select_related("author").prefetch_related("categories")

# 6
Post.objects.filter(comments__isnull=True)
# or: Post.objects.annotate(n=Count("comments")).filter(n=0)

# 7
Post.objects.annotate(like_count=Count("likes")).order_by("-like_count")

# 8
User.objects.filter(comments__isnull=False).distinct().values_list("username", flat=True)

# 9
Category.objects.annotate(
    published_count=Count("posts", filter=Q(posts__status=Post.Status.PUBLISHED))
)

# 10
Post.objects.prefetch_related(
    Prefetch("comments", queryset=Comment.objects.filter(body__icontains="great"))
)
```
</details>

Query 9 uses `Count(..., filter=Q(...))`, a conditional aggregate that is new today. If it surprised you, that's a good thing to note down.

## Part 4: Django ORM vs SQLAlchemy, 5 differences

Write your own five first, then compare. Here is a reference set:

| # | Topic | Django ORM | SQLAlchemy |
|---|---|---|---|
| 1 | **Pattern** | Active Record: the model instance saves itself (`post.save()`) | Data Mapper + Unit of Work: a `Session` tracks objects and flushes them (`session.add(post); session.commit()`) |
| 2 | **Session** | Implicit; you never manage one | Explicit `Session` you create, pass around, and close |
| 3 | **Query style** | Lookup strings: `filter(title__icontains="x")` | Python expressions: `select(Post).where(Post.title.ilike("%x%"))` |
| 4 | **Eager loading** | `select_related` (JOIN) and `prefetch_related` (separate query) | `joinedload`, `selectinload`, `subqueryload`, configurable per query or per relationship |
| 5 | **Migrations** | Built in and automatic (`makemigrations`) | Separate tool (Alembic) that you set up and configure |
| 6 | **Scope** | Part of a full framework (admin, auth, forms all use it) | Standalone library; works with any framework |
| 7 | **Flexibility** | Opinionated; raw SQL and complex queries are harder | Fine-grained control, closer to SQL, supports multiple mapping styles |
| 8 | **Lazy loading** | Related objects lazy-load on attribute access, with the N+1 trap | Same trap by default, but you can set `lazy="raise"` to make it an error |

Pick your top five. For your own notes, I'd highlight 1, 2, 4, 5, and 6, because they shape how you structure code. One caveat: Django's `select_related` is close to `joinedload`, but `prefetch_related` is closer to `selectinload`, so the Day 4 comparison was only half right.
